# sqljs 适配器内置持久化钩子（而非自动保存）

sql.js 是纯内存数据库，持久化必须手动 `db.export()`。我们决定适配器不自动保存（不预设存储位置），而是提供 `onPersist(db)` 钩子：仅在有写操作的事务成功 COMMIT 后被 await 触发（exec 调用标记侦测写事务；ROLLBACK 与纯读事务不触发），参数传 db 实例而非导出后的二进制——导出时机与去向由调用方决定。钩子抛错包装为 `FlexTreeSqljsPersistError` 向上传播（此时内存已提交、快照未落地，调用方需可区分于「fn 失败已回滚」）。

## Considered Options

- **自动保存到预设位置**：被否决。存储位置（localStorage/IndexedDB/下载）因应用而异，适配器预设即越界。
- **每次事务结束都触发**：被否决。纯读事务 COMMIT 后导出快照是纯浪费（O(库大小)），且 ROLLBACK 后导出的快照与回滚前等价、误导调用方。
- **fire-and-forget 触发**：被否决。并发下快照可能乱序落盘（后发先至覆盖新数据），且错误传播位置不确定。
- **钩子错误静默吞掉**：被否决。用户以为已保存，刷新后丢数据，运行期才暴露。

## Consequences

- `write()` 返回即「持久化已尝试完毕」（成功或已抛错），时序确定。
- 慢钩子会拖慢每次写事务——这是 await 语义的代价，调用方自行权衡钩子内做节流/异步队列。
